Upload rules

Share links must stay inside free-plan rules.

3 checks
1

File 50 MB se zyada upload na ho.

Verify that the uploader blocks files above the free upload limit and communicates the restriction clearly.
Pending
Expected result Files above 50 MB should be rejected on the free flow before or during upload with a visible, accurate error message. Files at or below 50 MB should still work normally.
Suggested test Try one file just under 50 MB, one exactly near the limit, and one clearly above the limit. Confirm both drag-and-drop and click-to-browse behavior.
2

30 minutes ke baad link expire ho jaye.

Validate that the free link lifetime expires when expected and that the expired state is clear to the receiver.
Pending
Expected result A free link should stop working after 30 minutes and show a proper expired state rather than a broken page or silent failure.
Suggested test Create a free link, confirm it works immediately, then re-open it after the expiry window. If you have admin tools or logs, confirm expiry timing server-side too.
3

One-time link sirf ek dafa download allow kare.

Check that a one-time link is consumed after the first successful download and cannot be reused.
Pending
Expected result The first successful receiver session can download the file. Any second attempt should show a consumed or expired state and must not deliver the file again.
Suggested test Open the same one-time link in two sessions or browsers. Confirm race behavior too: whichever actually completes first should consume the link.
Realtime visibility

Sender aur receiver dono ek waqt mein dekh sakein.

1 check
4

At the same time sender and receiver dekh sakain.

Confirm live progress sync between uploader and receiver without stale state, refresh-only updates, or blocked download handoff.
Pending
Expected result The sender sees upload progress while the receiver can open the share link immediately and observe real-time progress or readiness without needing manual refreshes.
Suggested test Start a larger upload, open the shared link in another device or incognito session right away, and compare progress indicators on both sides.
Accounts and billing

Signup, plans, and licensing should feel predictable.

3 checks
5

Sign up aur sign in sahi kaam kare, email aur direct dono se.

Validate normal auth, error handling, account creation, and the direct sign-in path if it exists.
Pending
Expected result New account creation succeeds, login works reliably, invalid credentials show correct errors, and both email-based and direct entry paths behave consistently.
Suggested test Test fresh registration, repeated login, logout, wrong password, and any direct or magic-link flow mentioned in the product.
6

Free plan main sirf free wali cheezein hon, kuch paid na ho.

Check that free-tier users do not accidentally unlock paid-only features and that upsell boundaries are accurate.
Pending
Expected result Free users should only access free-plan capabilities. Paid-only features should be clearly marked, blocked correctly, and never behave as silently broken.
Suggested test Review upload limits, expiry settings, dashboard controls, and any premium toggles. Confirm nothing paid appears unlocked for a free account.
7

License activation sahi kaam kare.

Validate that a valid license upgrades access correctly and invalid or reused keys are handled safely.
Pending
Expected result Valid activation updates the account state immediately or after a clear sync step. Invalid licenses should fail with helpful messaging and no partial upgrade.
Suggested test Try a valid license, an invalid license, and if possible a previously used or expired license. Confirm what changes in UI and account entitlements.

White-label features check karein: domain attach + verify, design page, file links, analytics, Google Analytics.
